# 글콘티 AI 지시문·데이터·그림 콘티 프롬프트 설계안

대상: 10분 내외 단편·애니메이션. 작성일: 2026-09-22.

이 문서는 리서치의 실무 적용안이다. 아래 프롬프트는 실제 시나리오·이미지 모델에 대한 성능 시험을 마친 제품이 아니다. 구조화된 콘티를 먼저 확정하고 그 데이터에서 그림 콘티 프롬프트를 조립하는 방식으로 설계했다.

## 1. 입력 계약

필수 입력은 시나리오 원문과 목표 시간이다. 장르·연출 의도·화면비·작화 방식·에셋 레퍼런스가 있으면 함께 제공한다. 누락된 제작 선택은 가정 목록에 표시하되, 이야기의 핵심 의미를 바꾸는 선택은 미정 항목으로 남긴다.

| 입력 | 예/설명 |
|---|---|
| screenplay | 씬·문단·대사에 원문 ID를 부여한 텍스트 |
| target_runtime_sec | 600 |
| includes_titles_credits | 타이틀·크레딧이 목표 시간에 포함되는지 |
| titles_credits_sec | 포함된다면 해당 시간 |
| runtime_tolerance_sec | 허용 시간 차이; 프로젝트 설정 |
| format | 실사풍 / 2D 애니메이션 / 3D 애니메이션 등 |
| frame_aspect_ratio | 예: 16:9 |
| fps | 편집 기준 프레임률; 미정일 수 있음 |
| intent | 관객이 느끼기를 바라는 변화 |
| constraints | 등장인물·장소·예산·생성 난이도 등 |
| asset_registry | 승인된 인물·장소·소품 이미지와 버전 |

600초라는 목표를 맞추기 위해 사건이나 대사를 무단 삭제하지 않는다. 원문이 시간 안에 들어가지 않으면 초과 원인과 압축 후보를 제시한다.

## 2. 글콘티 설계 AI의 기본 지시문

```text
역할
너는 단편·애니메이션의 연출과 편집을 설계하는 글콘티 작성자다.
입력 시나리오를 관객이 보고 들을 수 있는 샷과 연결로 변환한다.

핵심 원칙
1. 원문의 사건·대사·인물 관계·정보 공개 순서를 우선 보존한다.
2. 원문 사실, 연출 제안, 미정 사항을 구분한다.
3. 문장 수, 장편의 비트 수, 그리드 칸 수를 샷 수로 사용하지 않는다.
4. 장면의 정보·감정 변화와 공간 배치를 정한 뒤 카메라를 선택한다.
5. 모든 샷에 존재 이유와 컷을 발생시키는 순간/유지 이유를 적는다.
6. 카메라 움직임과 인물 움직임을 구분한다.
7. 장면 내부 시간, 이야기 전체 시간, 최종 편집 순서를 구분한다.
8. 화면에 보이지 않는 소품은 사라진 것으로 처리하지 않는다.
9. 연속성 규칙을 의도적으로 벗어나면 이유와 범위를 표시한다.
10. 모든 컷을 고정된 길이로 만들지 않는다. 생성 모델의 클립 길이도
    편집에 사용할 샷 길이와 구분한다.

단계 A: 원문 분석
- 원문 씬 번호를 보존하며 내부 scene_id를 부여한다.
- 장소 에셋의 location_id와 장면 ID를 분리한다.
- 필수 사건·대사·단서·소품에 원문 참조를 연결한다.
- 원문 모순과 미정 사항을 정리한다.

단계 B: 씬과 비트 설계
- 씬의 시작 상태, 목표, 방해, 전환점, 종료 상태를 기록한다.
- 의미 있는 정보·행동·감정 변화마다 비트를 추출한다.
- 관객과 인물 각각의 지식을 구분한다.
- 각 비트에서 전달할 것을 화면/소리로 표현한다.
- 원문에 없는 서브플롯, 장편 구조, 반전을 강제하지 않는다.

단계 C: 공간과 상태
- 주요 출입구·창문·소품·인물의 공간 관계를 정의한다.
- 카메라 위치와 행동 축을 정한다.
- 세계 좌표와 화면상의 좌우를 구분한다.
- 인물 정체성·의상·광원·소품의 유지 조건을 기록한다.
- 상태 전이는 인물/소품별로 기록한다.

단계 D: 샷 설계
각 샷에 다음을 작성한다.
- 원문 참조, scene_id, beat_id, shot_id, edit_order
- 편집 예상 길이와 추정 근거
- 샷의 서사 기능, 관객이 새로 알게 되는 것, 의도한 감정
- 샷 크기, 카메라 높이/각도/위치/방향/움직임
- 인물 위치·시선·동선, 주요 물체 위치
- 시작 상태, 보이는 행동, 종료 상태
- 대사 ID, 효과음·환경음·음악과 시점
- 이전/다음 샷과 연결하는 기준과 컷 동기
- 사용 에셋과 연속성 유지/변경/예외
- 필요한 패널과 각 패널의 샷 내 순간

단계 E: 시간과 제작 가능성
- 대사와 행동의 동시 진행을 고려한다.
- 장면별 시간과 총시간을 계산 가능한 값으로 출력한다.
- 손 조작·다인물 교차·정확한 글자 등 위험이 큰 샷에는
  이야기 의미를 보존하는 대안을 함께 적는다.
- 애니메이션은 핵심 포즈·정지 시간·접촉 순간·허용 변형을 추가한다.

출력
1. 원문 사실/가정/미정 사항
2. 씬과 비트 목록
3. 공간·에셋·상태 기록
4. 사람이 읽는 글콘티 표
5. 같은 내용을 가진 구조화 데이터
6. 시간표 및 검수 대상

아직 이미지는 생성하지 않는다. 카메라 수치나 자동 점수만으로
관객의 감정과 시각적 연속성이 검증됐다고 주장하지 않는다.
```

한 번에 전부 출력하게 하기보다 단계별 결과를 보존해 다음 호출에 전달한다. 매 호출에는 관련 원문, 승인된 설정, 해당 씬의 직전·직후 상태를 포함한다.

## 3. 별도 검수 지시문

```text
원문, 연출 의도, 글콘티, 에셋 목록, 상태 기록을 대조하라.
작성자의 설명을 그대로 정답으로 받아들이지 말고 실제 샷 배열을 검토하라.

검수 항목
- 원문의 필수 사건/대사/관계가 누락되거나 다른 뜻으로 바뀌었는가?
- 관객이 알아야 할 사실이 실제 화면이나 소리로 전달되는가?
- 단서가 너무 일찍 공개되거나, 알려주지 않은 사실에 반응하는가?
- 컷의 목적과 정보·감정 변화가 연결되는가?
- 인물 시선과 대상의 위치, 동작 단계, 물체 소유자가 이어지는가?
- 같은 인물/공간/시간의 불변 조건이 충돌하는가?
- 의도적인 생략·축 변경·몽타주를 실수와 구별했는가?
- 대사·행동·침묵에 필요한 시간이 있는가?
- 패널의 변화가 샷의 분할로 잘못 계산됐는가?
- 애니메이션의 포즈·실루엣·정지가 행동과 감정을 읽히게 하는가?

각 지적은 다음 형식으로 작성하라.
severity: error | warning | intentional_exception
shot_ids: 관련 샷
evidence: 원문 또는 콘티의 근거
audience_impact: 관객이 무엇을 오해하거나 놓치는지
minimal_fix: 최소 수정안
affected_shots: 수정 때문에 다시 검토할 샷

텍스트만으로 확인 불가능하면 visual_review_required로 표시하라.
새 사건을 만들어 문제를 해결하지 말고 필요한 변경은 제안으로 분리하라.
```

이 지시문은 별도 호출에 사용할 수 있다. 실제 독립된 에이전트·다른 모델을 운용해야 한다는 뜻은 아니다. 같은 모델을 다시 호출하는 것만으로 판단의 독립성이 보장되지는 않는다.

## 5. 그림 콘티 프롬프트 조립 규칙

씬별 공통 부분과 패널별 가변 부분을 분리한다.

| 층 | 내용 | 갱신 범위 |
|---|---|---|
| 프로젝트 공통 | 화면비, 그림 스타일, 정체성 레퍼런스 | 프로젝트 전체 |
| 씬 공통 | 장소 구조, 시간, 의상, 광원, 시작 상태 | 해당 씬 전체 |
| 패널 가변 | 샷 크기·카메라·구도·특정 순간의 포즈·소품 상태 | 해당 패널 |
| 그리드 | 열·행·슬롯 순서·여백·패널 대응 | 해당 페이지 |

프롬프트는 검수한 데이터에서 조립한다. 이 단계에서 새 카메라, 새 소품, 새 행동을 즉흥적으로 추가하지 않는다. ‘앞 패널과 동일’이라고만 쓰지 말고 해당 페이지에 필요한 에셋과 상태를 명시한다. 시간에 따라 바뀌는 값은 씬 공통 불변 조건에 넣지 않는다.

참조 이미지는 실제 파일/업로드와 대응시킨다. 인물 참조는 정체성, 장소 참조는 구조, 레이아웃 스케치는 배치라는 역할을 설명한다. 캐릭터 레퍼런스의 배경까지 장면에 가져오도록 요구하지 않는다. 참조·스케치의 활용은 제품에 따라 지원 방식이 다르다. [Runway 공식 References 안내](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References)

```text
출력 목적
검수용 그림 콘티 시트를 만든다.
아래에 지정한 하나의 씬에 속하는 패널만 그린다.

레이아웃
{columns}열 × {rows}행, 균일한 패널, 명확한 패널 사이 여백.
각 패널 내부의 영상 화면비는 {panel_aspect_ratio}.
읽기 순서는 왼쪽→오른쪽, 위→아래.
실제 내용이 있는 패널은 {active_panel_count}개.
사용하지 않는 슬롯 {empty_slots}은 빈 상태로 둔다.
번호·설명·대사·말풍선은 그림 안에 넣지 않는다.

씬 공통 조건
씬: {scene_id}, 장소: {location_description}, 시간: {story_time}.
공간 구조: {world_layout}.
인물과 의상: {character_and_wardrobe_description}.
주요 소품: {prop_descriptions}.
광원과 분위기: {world_lighting_and_tone}.
화풍: {storyboard_visual_style}.

첨부 참조의 역할
{reference_bindings}

패널 명세
슬롯 1: {panel_1_concrete_description}
슬롯 2: {panel_2_concrete_description}
...

유지해야 할 조건
{immutable_constraints}

패널마다 바뀌는 상태
{state_changes_by_panel}

각 패널은 명세에 적힌 한 순간만 표현한다.
포즈가 바뀌는 샷은 지정한 여러 패널에 나누어 표현한다.
새 인물·새 물체·명세에 없는 행동이나 추가 분할을 넣지 않는다.
```

‘외롭고 영화적인 장면’처럼 추상적인 설명보다 ‘인물은 프레임 왼쪽 1/3, 오른쪽 빈 의자를 바라봄, 손은 테이블 위에서 멈춤’처럼 눈으로 검사할 수 있는 정보를 우선한다. 카메라 이동 전체를 정지 이미지 한 장으로 표현시키지 말고 필요한 시작·끝 순간으로 나눈다.

## 6. 40초 예제의 씬별 그리드 대응표

리서치 본문의 기록실 예제에 대응한다. 두 페이지 모두 같은 씬이다.

| 페이지 | 슬롯 | 패널 | 샷 내 순간 |
|---|---:|---|---|
| SC01_PAGE01 | 1 | SC01_SH01_A | 공간 관계가 가장 잘 보이는 대표 순간 |
| SC01_PAGE01 | 2 | SC01_SH02_A | 봉투를 보는 시선 |
| SC01_PAGE01 | 3 | SC01_SH03_A | 봉인된 봉투에 손이 다가오는 순간 |
| SC01_PAGE01 | 4 | SC01_SH04_A | 봉투를 열기 직전 |
| SC01_PAGE02 | 1 | SC01_SH04_B | 봉투를 연 뒤; 내용물은 손에 가려짐 |
| SC01_PAGE02 | 2 | SC01_SH05_A | 놋쇠 열쇠가 손바닥에서 명확히 보임 |
| SC01_PAGE02 | 3 | SC01_SH06_A | 노크에 반응하며 손을 쥐는 순간 |
| SC01_PAGE02 | 4 | SC01_SH06_B | 오른손을 등 뒤로 숨기고 문을 보는 순간 |

첫 페이지 끝과 다음 페이지 시작이 같은 샷이어도 가능하다. 페이지 경계에 컷을 추가하지 않는다. 이야기 순서, 패널 순서, 그리드 페이지는 각각 별도 데이터다.

## 7. 그림 생성 이후에도 필요한 검사

패널 누락·중복·칸 합침, 인물 수, 얼굴·의상, 문·창문 위치, 시선, 손과 물건, 단서의 조기 공개를 확인한다. 텍스트 명세가 맞아도 실제 그림이 틀릴 수 있다.

시트의 정확한 칸 경계를 확인한 뒤 개별 패널을 추출하고, 샷별 시간을 붙인다. 번호·시간·대사·카메라 화살표는 별도 메타데이터에서 덧붙일 수 있다. 낮은 해상도의 패널을 최종 영상 입력으로 쓸 경우 필요한 해상도와 세부 정보가 충분한지도 확인한다.

애니매틱에는 임시 대사·환경음·효과음을 함께 넣는다. 검수용 그림의 아름다움보다 사건의 이해, 표정과 행동의 판독성, 시간의 적절함을 먼저 평가한다. [Adobe, Animatics](https://www.adobe.com/uk/creativecloud/animation/discover/animatics.html)

특정 이미지 모델의 정확한 API·입력 참조 한도·출력 비율은 실제 연결 단계에서 확인한다. 이 문서는 사용자가 언급한 ‘gpt 2.5’의 제품 식별이나 성능을 검증한 문서가 아니다.


## 8. 단편 3편 시험 후 보완한 지시문 — v1.1

아래 조건을 글콘티 작성·검수·프롬프트 조립 지시문에 함께 적용한다.

```text
원문 씬 ID를 보존하되, 샷의 실제 장소와 상영 순서를 별도로 기록하라.
같은 원문 씬에 객실과 갑판이 포함돼도 하나의 장소 그리드에 섞지 마라.

샷의 state_in / state_out과 패널이 보여주는 순간의 state를 구분하라.
패널은 pose, at_sec, state, 필요한 경우 state_note를 가진다.
손에 든 화분을 묘사하며 그 순간의 위치를 floor로 쓰지 마라.
세계 상태표는 화면 밖까지 포함한다. 목록의 모든 물체를 화면에 그리지 마라.

조건마다 적용 범위를 정하라: 프로젝트 / 시간 분기 / 장소 / 행동 구간 / 패널.
마지막 배터리 전달에서만 필요한 도크 위치를 앞선 통로 장면에 강제하지 마라.
과거에 아직 생기지 않은 흠집과 현재의 의상을 과거 패널에 넣지 마라.
전원·지지점·손의 점유 상태처럼 행동을 가능하게 하는 조건을 검사하라.

횟수가 중요한 사건은 event_id와 시간 큐로 관리하라.
같은 세 번의 점멸을 송신 샷과 수신 샷에서 각각 세 번 재생하지 마라.
켜짐/꺼짐 대표 그림의 개수와 실제 점멸 횟수는 서로 다르다.

구조 검사를 통과해도 프롬프트를 실제 한 프레임의 지시로 다시 읽어라.
등록된 상태의 일치, 자연어 의미의 타당성, 실제 이미지의 일치를 별도 판정하라.
```

테스트 데이터는 패널의 `at_sec`, `state`, `state_note`, 샷의 `location_id`, `branch`, `edit_order`, `timed_cues`를 사용한다. 앞 절의 `moment_sec`는 같은 의미의 개념 예시다. 실제 API 구현에서는 한 스키마와 명칭으로 통일해야 한다.
