## 2. 테스트 1 — 의자 하나

**이야기:** 돌아가신 어머니의 수선집을 정리하는 자매. 동생은 의자를 가져가려 하고 언니는 막는다. 의자를 함께 붙잡다 손상된 다리가 드러나면서 언니가 붙드는 이유가 달라 보인다. 두 사람은 함께 수리하고, 마지막에 같이 밥을 먹기로 한다.

**시험 의도:** 인물의 설명보다 손·시선·소유권의 변화가 관계를 전달할 수 있는지 확인했다. 언니는 화면 왼쪽, 동생은 오른쪽을 기본으로 하고 문·작업대의 위치를 고정했다.

**초안의 문제와 수정:** 코트를 벗은 뒤에도 같은 외형 명세가 적용되고, 바닥의 의자가 작업대에 올라가는 행동이 빠져 있었다. 또 발끝에서 손가락으로 바뀌는 화면을 고정 클로즈업 하나로 작성했다. 의상 상태와 회색 니트 에셋을 추가하고, 의자를 함께 들어 올리는 샷을 넣었으며, 발과 손을 각각의 샷으로 분리했다. 수리 시간 생략도 명시했다. 반복되는 멈춤을 줄여 샷 수는 늘었지만 전체 시간은 7초 짧아졌다.

**컷 연결의 핵심:** 동생이 의자를 가져가려 함 → 언니가 좌판 아래를 받침 → 벌어진 다리의 인서트 → 함께 내려놓는 투샷. 관객은 처음의 제지를 ‘소유욕’으로 읽었다가 ‘망가지지 않게 하려는 행동’으로 다시 읽을 수 있다. 여기서 다리의 문제를 처음부터 공개하면 그 재해석의 효과가 약해진다.

**완성도 판단:** 세 작품 중 감정 변화와 물체의 역할이 가장 분명하다. 다만 가족의 유품을 고치며 화해하는 설정은 익숙하고, 멈춤이 연기에 의해 채워지지 않으면 평면적으로 보일 수 있다. 글콘티 검토를 마쳤지만 대사 리딩과 표정 타이밍의 적정성은 미확인이다. 애니매틱에서는 ‘언니의 이유가 언제 바뀌어 보이는가’를 먼저 확인해야 한다.

## 3. 테스트 2 — 빛 배달

**이야기:** 폐쇄된 온실의 작은 관리 로봇 핍이 잎 두 장의 화분을 빛이 있는 곳으로 옮긴다. 턱과 문을 통과했지만 창은 막혀 있다. 핍은 자신의 배터리가 작업등에 맞는다는 것을 알아보고, 그 배터리로 불을 밝힌 뒤 멈춘다.

**시험 의도:** 대사 없이 목표·실패·새로운 방법·선택이 읽히는지, 로봇의 물성이 결말까지 일관되는지 확인했다. 초반에 전원이 끊기면 집게가 열리는 행동을 보여주어 마지막 낙하의 원인을 준비했다.

**초안의 문제와 수정:** 즉시 정지하는 로봇이 배터리를 분리한 뒤 도크 쪽으로 옮기는 동작은 성립하지 않았다. 분리 전에 도크를 슬롯 아래에 정렬하고, 전원 단절 이후에는 집게의 수동 개방과 중력으로 배터리가 내려가게 바꿨다. 슬롯·집게·도크를 한 중경 안에 보여준 뒤 접점 인서트로 이어지도록 했다. 발판 시험과 화분 운반은 두 샷으로 나누고, 결말에서 같은 결과를 반복 확인하던 두 샷을 통합·삭제했다.

**컷 연결의 핵심:** 슬롯·도크·집게의 위치를 함께 제시 → 접점 분리 → 열린 집게에서 배터리 낙하 → 작업등 켜짐 → 멎은 로봇과 빛을 받은 잎. 결과의 감동에 앞서 원인을 관객이 읽을 수 있도록 구도를 배정했다.

**추가 통합 수정:** ‘도크가 몸 아래에 있다’는 조건이 초반 통로 프롬프트까지 들어간 문제를 발견했다. 이 조건을 마지막 전달 구간으로 한정했다. 손에 든 화분·판자·작업등을 바닥 상태로 기록했던 대표 패널도 바로잡았다.

**완성도 판단:** 무성 연출과 인과 검증에 가장 유용한 사례다. 그러나 배터리가 빠지는 방향과 수직 도크에 들어가는 방향이 실제 디자인에서 맞는지는 모형 배치나 그림으로 확인해야 한다. 희생의 결말도 익숙한 편이며, 정적인 여운의 길이는 아직 연출 추정이다. 40초를 줄인 것이 곧 감정 전달의 개선을 입증하지는 않는다.

## 4. 테스트 3 — 세 번의 불빛

**이야기:** 섬의 다락에 있는 누나와 배를 타고 돌아오는 남동생. 휴대전화가 작동하지 않는 저녁, 어린 시절 어머니가 가르친 ‘봤으면 짧게 세 번’이라는 불빛 약속으로 서로가 기다리고 있음을 확인한다.

**시험 의도:** 장소가 다른 두 인물과 회상을 오가면서 관객의 시간·공간 이해와 사건의 횟수를 유지할 수 있는지 확인했다.

**초안의 문제와 수정:** 원문 씬 묶음만 사용해 객실·갑판·다락이 같은 그리드에 섞였다. 실제 샷 장소를 별도로 기록하여 분리했다. 회상이 손전등 클로즈업으로 시작해 시점 전환이 늦게 읽힐 수 있어 아이·어머니·과거의 실내가 함께 보이는 샷으로 시작했다. 아직 흠집이 생기지 않은 손전등과 현재의 손전등 상태도 분리했다.

두 번째 응답을 보내는 컷에서 세 번, 받는 컷에서 다시 세 번 보여주면 관객에게 여섯 번의 신호가 된다. 송신자 컷은 누르기 직전에 끝내고 수신자 시점에서 세 번을 한 번만 보여주도록 수정했다. 마지막 확인 응답도 배 쪽에서는 빛이 끝난 뒤의 반응으로 받는다.

**컷 연결의 핵심:** 누나가 충전하느라 아래를 봄 → 배에서 첫 응답 시작 → 남동생의 두 번째·세 번째 점멸 → 아직 보지 못한 누나의 반응 부재. 이후 재전송을 별도 사건으로 설계해 ‘첫 응답을 놓쳤다’는 인과를 유지했다. 점멸의 켜짐/꺼짐 패널은 대표 이미지이며, 횟수와 간격은 별도 큐표에 기록했다.

**완성도 판단:** 세 작품 중 편집 구조는 가장 복잡하고 워크플로우의 약점을 가장 많이 드러냈다. 실제로 회상 진입·현재 복귀·첫 응답 실패가 명확한지는 무설명 애니매틱으로 확인해야 한다. 장면의 배치표만으로 관객 이해를 통과 판정할 수 없다. 최종 자기검토에서는 흠집이 생기는 순간 손전등을 누가 들었는지도 어머니로 명확히 했다.

## 5. 무엇을 검증했고 무엇을 검증하지 않았나

각 작품은 v1 작성 → 원문·콘티 대조와 연출 자기검토 → v2 수정 → 프롬프트·패널의 순간 상태 대조 → v3 확정의 과정을 거쳤다. 1차 자기검토에서 기록한 실제 발견은 각각 6·5·6건, 총 17건이다. 이후 통합 검토에서는 패널 상태, 구간 조건의 적용 범위, 신호의 시간 큐, 소유 행동의 명료성을 추가로 보완했다.

초안의 구조 검사가 통과해도 이러한 문제가 남았다. 이는 ‘선언한 상태끼리 일치한다’와 ‘원문의 행동·연출이 성립한다’가 다르기 때문이다.

## 7. 실행 도구와 범위

이 폴더의 Python 코드는 직접 작성한 세 작품을 구조화하고, 수정본·문서·프롬프트·검사 결과를 출력하는 시험 도구다. **임의의 시나리오를 AI API로 변환하는 범용 글콘티 프로그램은 아니다.** 이번에는 작성과 연출 판단을 대화 중 AI가 수행했고, 코드가 정리·집계·검증·출력을 담당했다.

- case01.py / case02.py / case03.py: 창작한 원문과 초안 연출 데이터.
- harness.py: 데이터 정리, 검수, 글콘티·시간표·그리드 프롬프트 출력.
- revise.py: 실제 자기검토에서 결정한 v1→v2 수정과 이력.
- finalize.py: v2→v3 패널·프롬프트 통합 보완.
- mutation_tests.py: 보관된 작품을 바꾸지 않고 복사본으로 검수기 시험.

보관된 v1은 당시 상태를 비교하기 위한 기준이다. 현재 검수기는 이후 보강됐으므로 과거 v1을 현재 코드로 다시 검사한 결과와 당시 validation-v1.json의 검사 수가 다를 수 있다.

최종본을 재출력하려면 이 폴더에서 아래 명령을 순서대로 실행한다. Python 표준 라이브러리만 사용하며 외부 API 호출·이미지 생성 비용은 없다.

```sh
python3 finalize.py
python3 mutation_tests.py
```

## 8. 다음 제작 단계에서 가장 먼저 검증할 구간

전체 75페이지를 이미지로 만들기 전에 다음 세 구간을 우선 검증하는 것이 합리적이다. 이는 이번 글콘티 작업 후의 제작 순서이며, 수행 완료한 항목은 아니다.

1. 의자 하나: 제지 → 다리 손상 공개 → 함께 내려놓기. 관객이 언니의 행동을 재해석하는지 확인.
2. 빛 배달: 슬롯·도크 정렬 → 전원 단절 → 낙하 → 점등. 추가 설명 없이 물리적 원인을 읽는지 확인.
3. 세 번의 불빛: 첫 응답 실패 → 재응답 → 확인 응답. 회상/현재와 신호 횟수·관객의 인지 시점을 확인.

그림과 임시 소리를 붙인 애니매틱에서 문제가 발견되면 원본 샷·패널·큐 데이터를 수정하고 관련 프롬프트만 다시 출력한다. 본편 전체를 무조건 다시 생성하는 흐름은 필요하지 않다.
