# PLATING 워크플로우 정리 (다른 프로젝트 재사용용)

10분 AI 애니메이션 "PLATING"(2026-09~11)을 만들면서 굳어진 작업 규칙, 도구 함정, 프롬프트 구조, 검수 절차, 그리고 PLATING에서만 쓰는 예외 규칙까지 한 폴더에 모았다. 다른 프로젝트(작업 최적화 툴·워크플로우 구조화)에서 구조화 자료로 쓰는 것이 목적이다.

- 출처: 작업 핸드북 전체판 2026-11-06(노션 "작업 핸드북" 맨 위 첨부 md), 프로젝트 메모리(사용자 규칙·생성 함정·워크플로우 결정·날짜별 교훈).
- 11-08: 워크플로우 감사(`01 docs/audit/workflow_audit_2026-11-08.md`)의 사용자 답변 Q01~Q12를 반영했다. 본문에서 `(11-08 Qnn)`은 그 결정을 가리킨다.
- 이 폴더는 핸드북의 사본이 아니다. 핸드북 md·노션 본문의 정본은 노션이고 "핸드북 최신화와 워크플로우 최적화" 스레드만 고친다. 여기는 재사용 관점으로 다시 묶은 것이다.
- 이야기 내용(어떤 씬에 무엇이 나오는지)은 없다. 노션 시나리오 4차·컷표가 정본이다.

## 표기 규칙

- 표기 없는 항목: 다른 프로젝트에도 그대로 가져갈 수 있는 일반 규칙.
- `[예외: ...]`: PLATING에서만 쓰는 규칙. 괄호 안에 예외인 이유를 적었다(설정·스타일·특정 도구 계정·특정 사용자 취향 등). 가져갈 때는 자기 프로젝트의 값으로 바꾸거나 뺀다.
- `예(PLATING)`: 일반 규칙을 설명하는 PLATING 사례. 규칙은 일반, 예시만 고유.
- 날짜(예: 11-04)는 2026년 결정·실패 날짜다. 근거를 찾을 때 메모리·스레드를 날짜로 찾는다.

## 한 줄 요약 (가장 많이 쓰인 원칙)

1. 정본은 셋만 두고 나머지는 "백업본"이라 못 박는다. 충돌 순서를 문서 맨 앞에 적는다.
2. 규칙 문서 맨 앞에 "꼭 읽을 것" 약 60줄을 두고 매번 읽게 한다. 실패 대부분은 이미 적힌 규칙을 못 봐서 생겼다.
3. 크레딧이 드는 일은 명시 승인("생성해") 뒤에만. 버튼 누르기 전 점검 8줄을 프롬프트 바로 위에 칸으로 둔다.
4. 코드로 되는 수정은 코드로. 편집본을 또 편집하지 않고 원본에서 다시 한다. 입력은 가장 큰 원본만.
5. 글로 적은 크기·위치·방위는 지켜지지 않는다. 치수 기반 3D 블록아웃으로 잡고 그 위에 질감만 입힌다.
6. 레퍼런스 그림은 그 그림의 카메라와 질감을 끌고 온다. 역할을 한 줄로 못 박고, 안 되면 뺀다.
7. 흔들릴 생성은 둘로 나눈다. 초 단가가 같아 비용은 같고 실패한 쪽만 다시 돌린다.
8. 교훈은 배운 그 턴에 메모리에 적고, 규칙 문서는 한 담당이 하루 한 번 모아 갱신한다.
