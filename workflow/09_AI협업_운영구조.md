# 09. AI 협업 운영 구조

PLATING은 사용자 1명 + Claude 프로젝트(코디네이터 1 + 작업 스레드 여럿) + 사용자 PC의 Claude Code(Remote Control) + 외부 AI(Codex, Gemini TTS)로 돌렸다. 여기서 굳어진 운영 방식.

## 1. 역할 분담

| 역할 | 하는 일 | 못 하는 일 |
| --- | --- | --- |
| 사용자 | 결정·승인("생성해"), 웹앱 생성(Higgsfield·AICRON video_edit·업스케일), 손본 파일 드라이브 업로드, 확정 선언 | |
| 코디네이터(프로젝트 채팅) | 스레드 생성·해석, 메모리 읽기·쓰기 | 작업 자체 |
| 작업 스레드(클라우드) | 프롬프트 작성, 코드 합성·검수, AICRON MCP 생성, 아티팩트, 메모리 기록 | 영상 입력(video_edit), bpy, 드라이브 바이너리 업로드, 노션 PNG |
| PC Remote Control | Blender 렌더·시뮬, ffmpeg(Blender 내장), G: 드라이브 쓰기, 크롬으로 아티팩트 파일 받기 | 클라우드 스레드가 SendMessage로 지시 못 함(instructions로만) |
| Codex(외부) | edit 프롬프트 작성·생성(10-31 사용자 지정), Blender 인계 작업 | 아티팩트·노션 열람 |
| 핸드북 스레드 | 하루 한 번 핸드북 md·노션 본문 갱신 | |

- `[예외: 11-06 분담]` PC 영상 작업(ProRes 변환·검수)과 Blender(연회장) 스레드를 분리. 같은 노션·PC 폴더를 두 스레드가 고치면 덮어쓴다.
- 스레드는 씬·주제 단위. 같은 노션 페이지를 두 스레드가 동시에 고치지 않게 범위를 씬으로 나눈다.

## 2. 메모리 운영

- 주제별 파일 하나(사실 하나당 파일이 아니라). frontmatter(name, description, type), 본문에 **Why**·**How to apply**, `[[다른 메모리]]` 링크.
- MEMORY.md 색인 한 장에 경로·사용자 규칙·생성 함정·설정 결정·미결을 압축. 스레드는 작업 전에 색인 + 해당 주제 파일을 읽는다.
- 교훈은 배운 그 턴에. 날짜(MM-DD)와 사용자 발언을 짧게 인용해 근거를 남긴다. 상대 날짜 대신 절대 날짜.
- 옛 내용이 된 메모리는 지우거나 "폐기"라고 적는다. 11-05에 옛 메모리("시트가 바뀌면 DB도 맞춘다") 때문에 스레드가 백업 DB 수정을 잘못 제안했다.
- 비밀(토큰·키)은 메모리에 쓰지 않는다.

## 3. 스킬 (저장소 `.claude/skills/`)

- 사용자 선호: 모든 작업에 caveman(짧게), i-have-adhd 적용. ponytail은 대본 앱(sangsang-voice) 개발 때만(11-04). 세션에 기본 설치돼 있지 않아 저장소 프로젝트 스킬로 넣었다(PR #3). 명령이 안 잡히면 세션이 main 기준인지 확인.
- `[예외: 사용자 취향]` ponytail의 "요청 없는 추상화 금지"와 사용자 선호(Interface/abstract class) 충돌은 미결.

## 4. 스레드 소통 규칙

- 첫 턴에 체크리스트, 결과·막힘·질문이 있을 때만 답글. 사용자가 자리를 비우면 짧게.
- 되돌릴 수 있는 일은 하고 보고. 되돌릴 수 없는 일(크레딧, 외부 발송, 삭제)만 기다린다.
- 해석이 둘이면 가능성 높은 쪽으로 시작하고 어느 쪽인지 말한다.
- 실패는 도구 이름·오류 그대로. 추정이면 "추정"이라고 쓴다.
- 비판적 피드백. 사용자 요청에 허점이 있으면 반박한다.
- 아티팩트 제목에 상태 꼬리표(01 문서).

## 5. 인계 묶음 (외부 AI·PC로 넘길 때)

- `handoff/<내용>_codex_<날짜>/` 안에 README + 입력 파일 + ZIP. README에는 목적, 입력 목록(경로), 출력 규격, 지켜야 할 규칙 요약, 확인 안 된 것.
- 핸드북 md를 같이 넣는다(이야기·컷은 없으니 컷표 내용은 따로).
- 빠진 레퍼런스는 README에 "없음, 드라이브에서 찾을 것"으로 적고 찾은 경로를 핸드북에 추가하게 한다.
- 예(PLATING): `handoff/plating_video_codex_1031.zip`(약 130MB, 핸드북·S#01~03 프롬프트·레퍼런스 43장). 빠진 것 4개는 Codex가 드라이브에서 찾도록 지시.

## 6. Codex 작업 순서 (사용자 10-31)

1. 지정 컷의 컷표(빨간 칸 포함)와 앞뒤 컷을 읽는다.
2. 새 생성인지 edit인지 정한다(06 문서 1절). 모르면 묻는다.
3. 새 생성은 05 문서 워크플로우·블록, edit은 06 문서 구조. 고정 블록은 원문 그대로.
4. 05 문서 체크리스트와 배운 것으로 자체 검수. 특히 이미지 번호, 초 표기, 시작·엔드 프레임, 화면 좌우.
5. 씬 md 파일 안에 클립을 아래로 쌓는다(기존 클립 안 지움). 첨부 목록과 생성 설정(모드·길이·해상도).
6. 생성 전에 한 줄로 확인(크레딧).
7. 결과를 보여 주고 틀린 곳은 원인(레퍼런스인지 문장인지)부터.
8. 확정되면 컷표 반영.

## 7. AI 단독 작업 순서 (사용자가 "씬 하나 다 만들어 둬"라고 맡길 때)

### 1단계: 컷표 읽기
- 컷표 fetch 결과 파일에서 "S#XX 수정" 토글 구간만 파이썬으로 잘라 읽는다. 앞 씬 마지막 컷, 뒤 씬 첫 컷도.
- 시나리오의 해당 씬도 읽고, 컷표와 다르면 컷표 수정 토글을 따른다.
- 컷표에 없는 것은 프롬프트 파일 맨 위에 "내가 정한 것"과 "사용자 답이 필요한 것"으로 나눈다. "스스로 판단"이라 했으면 정하되 근거와 함께.

### 2단계: 클립·길이·프롬프트
- 05 문서 1절 2~8단계. 프롬프트는 씬 md 한 파일에 클립 순서대로. 실제 보낸 전문은 `prompts/sXX_gen/클립_full.txt`.

### 3단계: 레퍼런스를 공개 주소로
- 드라이브 search_files로 같은 그림을 찾는다(영문·한글 둘 다). 씬 자료 폴더에 사용자가 모아 둔 사본이 있으면 그것. 크기가 비슷하면 같은 그림.
- curl로 image/* 확인. 받은 그림을 썸네일 모음으로 **눈으로 확인**. 이름만 믿지 않는다.
- 드라이브에 없는 것은 글로만 쓰고 파일에 "시트 없음".

### 4단계: 생성
- 승인 확인(그 씬 한 바퀴는 승인된 것). 비용 = 초 × 단가.
- 여러 클립을 동시에. 타임아웃 나도 다시 보내지 않고 history로 회수.

### 5단계: 검수와 기록
- 결과를 `video/<씬>/raw/`에 원래 이름으로. 검수용 타일은 ffmpeg `fps=1,scale=320:-1,tile=5x2`로 컷마다: 화면 방향, 인물 크기, 시트와 같은 옷, 레퍼런스 구도 베꼈는지, 동작이 초에 맞는지.
- 결과·문제·다음 수정안을 프롬프트 파일 클립 아래에, 아티팩트 갱신. 영상은 사용자가 볼 수 있게 함께.
- 사용자가 확정하면 컷표 반영.
