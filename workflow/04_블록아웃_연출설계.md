# 04. 블록아웃과 연출 설계

축척·배치가 맞아야 하는 공간이나 사진이 없는 각도는 도면 수치로 Blender 블록아웃을 만들고, 그 렌더 위에 질감만 입힌다. 글로 적은 크기·방위는 생성 모델이 지키지 않기 때문이다(03 문서 7절).

## 1. 블록아웃 규약

- 1단위 = 1m. +Y 북, +X 동, +Z 위. 원점·좌표 기준은 스크립트와 README에 적는다.
- 사람 축척 막대: 빨간 막대 1.8m. `[예외: 진우는 파란 막대 — 주인공 구분]` 생성 입력용 렌더에서는 반드시 숨긴다. 남기면 Seedream이 사람으로 그린다.
- **수치는 스크립트 맨 위 상수에만.** 스크립트가 정본, .blend는 결과물. 스크립트가 씬을 초기화하고 다시 지으므로 .blend에서 손으로 옮긴 것은 다음 빌드 때 사라진다.
- 사용자가 확정한 치수만 반영. AI나 작업자 제안 치수는 "가정"으로 표시하고 확인.
- 사람 크기 물건(의자, 조리대, 계단, 테이블 폭·높이, 문)은 전체 축척을 바꿔도 고정.

## 2. 버전과 검산

- 고칠 때마다 파일 이름 버전을 올리고(`tower_hall_D80_v23.blend`), 이전 스크립트는 `_v1x_backup.py`로 남긴다.
- 빌드 끝에 콘솔로 핵심 치수 한 줄을 검산한다. 예(PLATING): `HALL_D=80.0`, 바닥 Z 44.8. v12~v19는 축척 인자가 빠져 이름만 D72이고 실제는 80으로 지어진 사고가 있었다.
- 렌더용 카메라는 스크립트에 카메라로 추가. 임시 카메라는 .blend에 저장되지 않는다.
- **블록아웃에서 만든 시트·렌더·스틸을 쓰기 전에 기준 버전을 확인한다(11-02).** 파일명 `vNN_` 접두사나 README. 최신 블록아웃과 구조가 다르면 다시 렌더하거나 차이를 적고 글로 바로잡는다. 기준 버전 없는 그림은 구조 레퍼런스로 쓰지 않는다. 왜: 하루에 수십 버전이 올라가(v32→v57) 옛 렌더로 만든 시트가 틀린 구조로 쓰였다.
- 도면(평면·단면도)은 그 버전의 블록아웃에서 읽은 값이라 블록아웃이 올라가면 뒤처진다. 기준은 폴더에서 가장 큰 버전 번호의 .blend·스크립트·README.

## 3. 렌더

- `[예외: 사용자 PC 환경]` 렌더는 사용자 PC Blender 5.2 LTS(`C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`, PATH에 없음)에서 Remote Control로. 클라우드 컨테이너에는 bpy를 설치하지 않는다. PC를 못 쓰면 Codex 인계 묶음(`handoff/<내용>_codex_<날짜>/` README + 입력 + ZIP).
- 생성 입력용 렌더: Workbench, Studio 라이트, Material color. 1920×1080, Seedream 입력용은 레퍼런스 스틸과 같은 2816×1584.
- Workbench는 유리를 불투명 면으로 그린다. 유리 표시/숨긴 렌더를 20:80으로 합성. 발광 띠는 EEVEE에서만 빛난다. Workbench에는 심도가 없어 초점은 글로 지정.
- 저장은 `renders_<내용>_<날짜>/`에 버전 접두사(`v22_`).
- EEVEE 81프레임이 4분(마감 5분 근접)이라 시뮬 미리보기는 Workbench로(11-05).

## 4. 생성 입력으로 쓸 때

- Seedream은 프롬프트보다 블록아웃의 형태를 따라 그린다. 형태가 틀리면 결과도 틀린다(달걀형 포투 → 부엉이, 관절 없는 다리 → 튜브). 형태가 중요한 부분은 블록아웃에서 먼저 맞춘다. 뷰마다 형태가 애매하면(받침 없는 난간 막대) 뷰마다 다르게 그린다 → 블록아웃에서 확정하고 다시 렌더.
- 블록아웃은 한 장만 넣고 재질·빛은 글로. 사진 레퍼런스를 같이 넣으면 사진 구도를 베끼고 블록아웃 형태를 무시한다(HOPE 골목 v13, 4장 모두 실패).
- 영상에서는 블록아웃을 시작 프레임으로 쓰지 않는다. 회색 질감과 낮빛을 끝까지 끌고 간다. 레퍼런스로만. 사용자가 그린 화살표·동그라미는 코드로 지운 판을 쓴다.
- 블록아웃 밖으로 보이는 것(잔디·탑 다리)은 프롬프트에서 무엇으로 바꿀지 적는다.

## 5. 질감 전 레퍼런스 보드 (매번, 11-04)

흐름: 사용자가 아래 요소로 컷을 말한다 → AI가 레퍼런스 보드로 보여 주고 합의 → 블록아웃 카메라 값으로 렌더 → 프롬프트 문장으로 옮긴다. 크레딧 쓰기 전에 연출 의도를 눈으로 합의해야 재생성이 줄어든다.

- 이미지 컷이면 카메라 무빙·영상 기법은 뺀다. 영상 컷이면 무빙·연기 영상까지.
- 한 장이 모든 조건에 맞을 필요 없다. 색감·화각·구도를 따로 보여 줘도 된다.
- 검색은 영어 키워드(dolly in, close-up, 35mm, eye level, low-key, rim light).
- 영화 스틸은 장르·색감으로 후보를 찾고 사용자에게 추려 달라고 한다.
- 출처: aicameramovements.com(무빙 46개), vvsvs.pro/cinematique(기법 150개), seedance-emotion-direction.vercel.app(연기 25개), jherr.github.io/depth-of-field(화각·심도), screenmusings.org(색 견본·장르), movie-screencaps.com. flim.ai·eyecannndy.com은 봇 차단 → 사람이 직접.
- **레퍼런스는 전부 실사다. 보는 용도로만, 생성 입력(@image)에 넣지 않는다.** Cinematique 템플릿도 실사 단어(ARRI, Kodak, 8K, 보케)가 66번 나와 문장은 쓰지 않고 개념만.

## 6. 구도와 무빙을 설명하는 요소

다 채울 필요 없다. 빠진 칸은 AI가 기본값으로 정하고 "내가 정한 것"으로 표시.

### 정지 구도 (한 프레임)

| 요소 | 말하는 법 | 블록아웃에서 |
| --- | --- | --- |
| 1. 무엇을 보나 | "진우 얼굴", "공물대 전체" | 카메라 목표점 |
| 2. 샷 크기 | ECU/CU/MCU/MS/FS/WS/EWS | 렌즈 mm와 거리(8절 표) |
| 3. 카메라 위치 | "계단 중간에서", "테이블 동쪽 끝 뒤에서" | 월드 X·Y |
| 4. 카메라 높이 | 눈높이(바닥+1.6m), 허리(0.8), 바닥(0.3), 위에서(몇 m), 수직 탑샷 | Z = 그 자리 바닥 + 높이 |
| 5. 앵글 | 수평 / 올려다봄 / 내려다봄(몇 도) / 더치 | pitch·roll |
| 6. 화면 방향 | "무엇이 왼쪽, 무엇이 오른쪽" `[예외: 연회장은 남→북 = 왼→오]` | 보는 방위 |
| 7. 인물 위치·크기 | "화면 왼쪽 1/3", "머리가 위 1/4" | 가이드선으로 확인 |
| 8. 전경 | "창살 너머", "어깨 너머(OTS)" | 사이에 놓을 물체 |
| 9. 초점 | deep focus / 대상만 선명 | 글로만(Workbench 심도 없음) |
| 10. 빛 방향 | "돔 등이 위에서", 출처가 화면 안에 | 글로 |

### 무빙 (AI Camera Movements의 네 칸)

| 칸 | 뜻 |
| --- | --- |
| 종류 | static, pan/tilt, zoom, dolly, truck/slider, pedestal/crane, arc/orbit, tracking/follow, push past, whip pan/crash zoom, handheld |
| 속도 | 일정 / 천천히 시작해 빨라짐 / 빠르게 끊어짐 |
| 고정할 것 | 움직이는 동안 바뀌면 안 되는 것 |
| 끝 구도 | 마지막 프레임을 정지 구도 10요소로 |

여기에 시작 구도, 길이(초), 무빙 시작·끝 초를 붙이면 한 무빙이 정해진다. 헷갈리는 쌍: zoom(렌즈만, 원근 안 바뀜) vs dolly(이동, 원근 바뀜), pan(고개) vs truck(몸 이동), tilt vs pedestal.

`[예외: 쓰지 않는 무빙 — tilt-shift(미니어처 룩), infinite zoom·pass-through(물체 속으로 파고들어 다른 세계. S#10 C005 동공 속 실패)]` 미니어처 금지는 스타일 결정이지만, 함정 자체는 일반.

### 연기 (Emotion/Direction 원칙)

- 연기 문장에는 보이는 몸의 동작만. 카메라·공간과 섞지 않는다.
- 감정 이름 대신 부위별 동작을 순서대로(눈썹 → 눈 → 입 → 턱·목 → 숨 → 머리 → 어깨), 마지막에 **유지되는 끝 상태**.
- `[예외: FACE RULE 때문에 하층민·요리사·하인은 눈·머리·어깨·숨만, 상류층은 반가면이라 눈썹 제외, 진우는 전부]`
- 손 문장은 다른 사람과 소품으로 번지니 인서트에만.

## 7. 블록아웃 렌더 뽑는 순서

1. 카메라는 스크립트 상수 `CAM_<컷>_start`, 무빙은 `_end`(arc·crane은 `_mid`). 위치(X,Y,Z), 목표점 또는 회전, 렌즈 mm, 센서 폭 36mm.
2. 위치는 대상 기준으로 계산(방위·거리). Z는 그 자리 바닥 + 카메라 높이(바닥이 기울면 그 점의 바닥 높이를 다시 잰다).
3. 샷 크기는 8절 공식. 기본값: 공간 컷 24mm, 인물 35mm, 클로즈업 50~85mm, 멀리서 당겨 보는 컷 135mm.
4. 무빙은 렌더 두 장 이상: zoom은 같은 위치 mm만 다르게, dolly는 같은 mm 위치만, pan·tilt는 회전만, arc·crane은 시작·중간·끝.
5. 렌더 두 벌: (a) 깨끗한 판(막대·표시 숨김, 생성 입력·영상 레퍼런스용) (b) 주석판(3등분 가이드, 1.8m 막대, 카메라 값 표기, 사용자 확인용).
6. 해상도·방식은 3절 그대로. 버전 접두사.
7. 보고: 카메라 값, 무엇이 보이고 무엇이 가려지는지, 내가 정한 값.
8. 영상에서는 깨끗한 판을 Seedream으로 질감 입혀 시작·끝 프레임을 만들고, 블록아웃은 레퍼런스로만.

## 8. 렌즈·거리·심도 계산

16:9, 풀프레임 36mm 센서. **화면 높이 = 거리 × 20.25 / mm**, **화면 폭 = 거리 × 36 / mm**.

| 렌즈 | 가로 화각 | 1m에서 폭×높이 | 용도 |
| --- | --- | --- | --- |
| 16mm | 97° | 2.25×1.27 | 좁은 실내 전체 |
| 24mm | 74° | 1.50×0.84 | 공간 와이드 |
| 35mm | 54° | 1.03×0.58 | 인물+공간 |
| 50mm | 40° | 0.72×0.41 | 눈에 가까운 화각, MCU |
| 85mm | 24° | 0.42×0.24 | 얼굴 CU, 배경 압축 |
| 135mm | 15° | 0.27×0.15 | 멀리서 당겨 봄 |

샷 크기별 목표 화면 높이(사람 1.8m): FS 약 2.2m, MS 1.1, MCU 0.7, CU 0.35, ECU 0.15. **거리 = 목표 화면 높이 × mm / 20.25.** 예: 35mm MCU = 0.7×35/20.25 ≈ 1.2m. 85mm 같은 MCU ≈ 2.9m, 배경이 더 당겨 붙는다.

심도 규칙:
- 넓은 공간을 24~35mm로 멀리서 찍으면 실제로는 거의 다 선명하다. 여기에 얕은 심도를 넣으면 미니어처로 보인다.
- 얕은 심도는 ECU·매크로와 망원(135mm)에만.
- 망원은 배경을 압축해 크게 당긴다.

## 9. 카메라 줄을 프롬프트로 옮기기

TIMELINE 구간마다 한 줄:
```
0–4s, @image1 (start frame). CAMERA: dolly in. Movement: the camera moves forward in a straight line toward Jinwoo at eye height (1.6 m). Speed: very slow, steady. Framing: keep height, lens (35 mm) and Jinwoo at the left third unchanged. End: medium close-up, chest up, the cage bars soft in the foreground.
```
- 종류 이름 하나, Movement·Speed·Framing·End 네 칸. End가 05 문서의 "구간 끝 상태".
- 고정 구간: "locked-off static shot. Hold one fixed camera position for the full segment; keep the same angle, height, lens distance and composition."
- 렌즈 mm와 거리를 적는다(미니어처를 막는 축척 단서).
- 초점은 결과로: "deep focus, foreground to background sharp" / "only the eye in focus, background soft". f값·카메라 기종·필름 이름은 쓰지 않는다.
- AVOID에 이 무빙이 무너지는 방식(zoom 컷에 "camera does not move forward", static 컷에 "no drift, no push in").
- 이 장의 숫자는 계산값이고 Seedance가 이대로 따르는지는 생성으로 확인하지 않았다(11-06 기준).
