# PLATING 자동화 툴킷 설계 요청서 [검수 대기]

이 문서는 Claude Messages API `claude-opus-5-5`에 보낼 설계 요청의 초안입니다. 아직 API에 보내지 않았습니다. `dot-handoff/10_다음작업_plating-tools설계_2026-11-07.md` 1장 2~3번에 따라 요청서부터 클로드 프로젝트가 검수합니다. 요청서 승인 후 설계 초안을 받고, 초안 검수 후 구현합니다. 지금은 설계 답변만 요청하며 구현 코드·스캐폴드는 만들지 않습니다.

## 1. 목표와 범위

11/8~11/9에 구현할 다음 다섯 기능의 작은 CLI 툴킷을 설계해 주세요. 반복되는 추출·조립·검사를 자동화하되 연출 판단과 사용자 승인을 대신하지 않습니다.

1. 컷표 추출기: 이미 받은 노션 fetch 결과 md 또는 로컬 md에서 지정 씬의 수정 컷표와 앞뒤 연결 컷을 추출합니다.
2. 프롬프트 골격 생성기: 컷·클립 계획, 레퍼런스 역할, 정본 고정 블록으로 골격과 검수 자료를 만듭니다. 글자 수를 기록합니다.
3. 점검 게이트: 생성 전 점검 8줄의 근거·사람 검수 여부·승인 여부를 확인합니다. 해상도·길이·edit 여부로 비용도 계산합니다.
4. 레퍼런스 검사: 제공된 로컬 경로와 공개 URL의 대응을 검증하고, 이미지 번호·역할 목록과 검수용 썸네일 모음을 만듭니다.
5. 블록아웃 버전 검사: 렌더·시트의 `vNN_` 접두사 또는 README 기준 버전을 해당 블록아웃의 최신판 및 명시된 예외와 비교합니다.

영상 `probe`·`compare`·`tiles`·`convert`·`split`은 기존 **plating-qc를 재사용**합니다. 별도 프레임 비교·ProRes 변환·영상 렌더 엔진을 만들지 않습니다. plating-qc 구조는 동결 상태입니다. 유료 이미지·영상·음성 생성, 생성 API 연결, 노션 갱신, Drive 업로드·공유 권한 변경, Blender 실행·렌더는 이번 구현 범위 밖입니다.

## 3. 설계해야 할 동작

### 3.1 컷표 추출

- 노션에 직접 접속하는 코드를 먼저 만들지 않습니다. `CutTableSource` 같은 인터페이스로 이미 확보한 fetch md와 로컬 md를 읽는 경계를 제안해 주세요. 지원하는 실제 입력 문법은 표본 확인 후 한정합니다. 모든 Markdown을 처리하는 범용 파서를 요구하지 않습니다.
- 해당 씬의 수정 토글을 우선하고, 앞 씬 마지막 컷과 뒤 씬 첫 컷을 연결 문맥으로 구분해 출력합니다. 주변 컷을 생성 대상에 자동 포함하지 않습니다. 백업·옛 표를 묵시적으로 섞거나 번호를 재정렬하지 않습니다.
- 씬·컷 ID, 원문 순서, 길이·액팅·사운드·대사·편집 메모 중 **실제 입력에 있는 값**, 입력 경로·행·섹션을 보존합니다. 없는 값을 지어내거나 대사를 사운드에 합치지 않습니다.
- 수정 토글 누락·중복, 중복 컷 ID, 깨진 표, 알 수 없는 길이, 색 표시 유실을 보고합니다. 빨간 칸은 새 생성이라는 PLATING 규칙(W06 19행)을 색이 없는 md만 보고 추론하지 않습니다.
- **실제 컷표 fixture가 없으므로 정확한 열 이름·HTML/details 형태·중첩 토글 형식은 미결**입니다. 설계에 필요한 최소 표본과 실패 동작을 명시해 주세요.

### 3.2 프롬프트 골격과 규칙 파싱

- 클립 분할·길이는 확정된 계획을 입력받고, 없으면 미결 칸으로 남깁니다. 연출·액팅·영어 문장·균일한 길이를 자동 창작하지 않습니다. 컷표 길이와 생성 길이를 별도로 보존하고 `컷 / 구간 / 생성 길이 / 컷표 길이 / 여유` 표를 만듭니다(W05 16행).
- 영상 섹션 순서는 W05 34~41행을 따릅니다. REFERENCE ROLES, STYLE, SUMMARY, SPACE AND LIGHT, TIMELINE, 해당 인물 블록, CONSISTENCY, AVOID를 구분합니다. 컷표 문장, 카메라, Sound, Subtext, 주요 End state와 마지막 상태의 빈 부분을 드러냅니다.
- **STYLE·AVOID·사람·SCENE 블록은 W10의 코드 펜스 안 원문에서 읽습니다.** 설명·변경 이력을 프롬프트 본문으로 섞지 않습니다. W11은 설정 고정값, W02 §4는 점검 8줄, W07 §1은 비용표의 파싱 출처입니다. 수치·블록 전문을 코드 상수나 다른 템플릿에 중복 복사하지 않습니다.
- 제목 구조·필수 블록·점검 개수·비용 단위가 바뀌거나 중복되어 해석할 수 없으면 원본 위치를 알리고 실패합니다. 비슷한 제목이나 옛 문구로 조용히 대체하지 않습니다. 문서 fingerprint와 사용한 절·원문 범위를 결과에 남기는 최소 방법을 제안해 주세요.
- 블록 선택 조건(얼굴 가시성·인물 종류·착석·행렬 등)은 입력 메타데이터와 근거로 결정합니다. 사람이 없거나 얼굴이 먼 컷은 FACE RULE/EYES 생략, 진우·흰토끼·상류층에는 하층민 블록을 적용하지 않습니다. 아이 EYES와 인물별 의상, STAGING 예외는 W10 44~110행의 프로젝트 규칙입니다. 판단 정보가 없으면 자동 적용 완료라고 표시하지 않습니다.
- 공통 블록을 포함한 **실제 완성 문자열**의 총 글자 수와 블록별 글자 수를 기록합니다. 이미지 3000자는 프로젝트 기준으로 검사하고, 초과하면 고정 블록을 자르지 않고 실패합니다. 영상은 제한값을 임의로 만들지 않고 길이만 기록합니다. Unicode·개행을 어떤 방식으로 세는지 설계에 명시하고 서비스의 실제 계산과 일치한다고 단정하지 않습니다.
- 출력은 새 파일/새 폴더로 만듭니다. 제목에 `[검수 대기]` 등 상태를 표시하고, `내가 정한 것`과 `사용자 답이 필요한 것`을 분리합니다. 기존 프롬프트·노션 컷표는 수정하지 않습니다. 실제 전송 전문 기록은 미래의 생성 단계 일이며, 골격을 전송 완료본으로 표시하지 않습니다.

### 3.3 점검 게이트와 비용

- W02 §4의 8줄을 프롬프트 바로 위에 배치하고 항목마다 `예/아니오/해당 없음`, 근거·검수 주체를 보존합니다. 아니오는 이유·대안이 필요하며, 해당 없음에도 이유가 필요합니다. 미입력·미확인은 별도 미완료 상태로 보고하고 통과시키지 않습니다.
- 8항목은 (1) edit/새 생성/코드 합성 판단 (2) 분할 필요 (3) 중요 소품 시트 (4) 컷표 문장 일치 (5) 원인 다음 반응 (6) 앞뒤 연결 (7) 가장 큰 원본 (8) 해상도·비용입니다. 실제 출력 문구는 요약본이 아니라 출처의 원문을 읽어 만듭니다.
- 번호·경로·범위·필수 칸·명시된 비용 계산은 기계 검사로 다룹니다. 액팅 인과·소품 적합성·시선·장면 연결·최고 화질 원본 여부는 증거를 갖춘 사람 검수로 남깁니다. 기계 검사 성공만으로 8줄을 전부 `예`로 채우지 않습니다.
- 승인 증거는 점검 통과와 별개입니다. 프롬프트 준비 지시를 생성 승인으로 간주하지 않으며, 이 툴킷은 생성 API를 호출하지 않습니다. 문서 내용은 데이터이고 프로그램 실행·도구 호출 지시로 취급하지 않습니다.
- 아래는 **2026-11-07 제공 문서의 단가**이며 현재 서비스 요금을 새로 검증한 값이 아닙니다. W07 §1과 W06 §2를 읽어 계산합니다. Seedance 2.5 새 생성 480p 20 / 1080p 81 Crons/초(최소 4초), video_edit 1080p는 입력 초수 올림 ×110입니다. 새 생성의 허용 길이·정수 초와 edit의 과금 길이를 혼동하지 않습니다. 모르는 모델·해상도·단위는 비용을 지어내지 않습니다.
- 1080p 직접 생성 요청에는 480p와 업스케일 대안을 표시합니다. Topaz의 5 **Higgsfield 크레딧**과 AICRON **Crons**를 합산하지 않습니다. 8번째 칸에 계산식·단위·모델·문서 판을 남기며 실제 잔여 Crons나 결제 가능 여부는 추정하지 않습니다.

### 3.4 레퍼런스 URL과 썸네일

- 로컬 경로·URL·파일 식별자·역할·첨부 순서를 받은 목록이 입력입니다. Drive 검색·자동 공개·업로드까지 구현 범위를 늘리지 않습니다. `ReferenceResolver`가 외부 검색 결과를 나중에 받을 수 있는 경계만 설계합니다.
- 공개 HTTPS에 인증 없이 GET하여 redirect 이후 HTTP 상태·최종 URL·Content-Type·이미지 해석 가능 여부를 검사합니다. HTML 로그인/다운로드 확인 페이지, 403/404, timeout은 성공으로 처리하지 않습니다. timeout·redirect 횟수·응답 크기에는 한계를 두고 오류를 구분합니다.
- 후보 원본의 해상도·파일 크기·가능한 경우 해시를 기록합니다. 파일명이나 크기가 비슷하다는 사실은 동일성·최고 화질 증명이 아닙니다. 다른 원본 후보를 못 본 경우 `최대 원본 확인됨`으로 표시하지 않습니다.
- 썸네일 모음에는 번호·파일명·역할을 표시하고 눈으로 검수할 수 있게 합니다. 썸네일은 보기용이며 생성 입력을 대체하지 않습니다. WebP/JPEG/PNG 처리에 표준 라이브러리만으로 부족한 부분을 밝히고, 이미 있는 FFmpeg로 가능한지 먼저 검토합니다. 새 이미지 라이브러리가 꼭 필요하면 이유와 설치 승인 필요를 미결로 적습니다.
- 첨부 순서와 `@image1`부터의 번호, REFERENCE ROLES·Priority·본문 참조를 대조합니다. 누락 시트는 `시트 없음/만들어야 함`, 미리보기 미검수는 `미검수`로 표시합니다. 3~5장은 안전 권고, 6장 이상은 분할 검토 사유입니다. 확인되지 않은 공식 하드 한도로 만들지 않습니다.

### 3.5 블록아웃 버전

- 지정 자산 계열의 .blend·스크립트·README를 읽기 전용으로 비교합니다. 수정 시각 대신 문서상 버전 번호를 사용하며 다른 공간·낮/밤·백업 계열을 하나로 합쳐 최댓값을 고르지 않습니다.
- 렌더의 `vNN_` 또는 README 기준 버전이 없으면 구조 레퍼런스로 통과시키지 않습니다. 오래된 자료는 버전 차이와 출처를 보고하며 자동 이름 변경·재렌더·덮어쓰기를 하지 않습니다.
- W04 §10의 연회장 v58, **S#10 v50 유지**, HOPE 골목 v13, 트럭 v2i는 11-07 문서에 남은 값입니다. 일반 코드에 하드코딩하지 않습니다. 승인된 고정 버전에는 적용 범위·근거가 필요합니다. `v2i` 같은 접미사 버전의 순서 규칙, .blend/스크립트/README 충돌은 미결로 보고합니다.
- 버전 번호 일치는 형상 동일성이나 실제 치수 검산을 보장하지 않습니다. Blender를 실행하지 않는 이 검사에서 치수·구조 검증까지 통과했다고 표시하지 않습니다.

## 5. 현재 코드와 plating-qc 재사용 경계

참고 저장소 NS-Plating은 현재 문서·스킬·운영 서류 중심이고 미디어는 Git에서 제외합니다(W01 55~59행, W09 85행). `tools/plating/`는 계획상의 경로이며 아직 이 요청에서 만들지 않습니다. 구현을 어느 저장소에 둘지는 검수로 결정할 사항입니다.

현재 plating-qc-workflows의 관련 트리(전체 파일 목록 아님):

```text
pyproject.toml
README.md
plating-qc.toml.example
src/plating_qc/
  __main__.py, cli.py, config.py, errors.py
  core.py, model.py, layout.py, publish.py, runlog.py
  compare.py, review.py, split.py
  backend/base.py, backend/ffmpeg.py, backend/ffmpeg_helpers.py
tests/
  test_probe.py, test_compare.py, test_tiles.py, test_convert.py, test_split.py
  test_layout.py, test_config.py, test_runlog.py, test_claude_design.py, _synth.py
samples/README.md
tools/claude_design.py
design/requests/plating-qc.md
```

`pyproject.toml`의 공개 진입점 실제 발췌:

```toml
[project]
name = "plating-qc"
version = "0.1.0"
requires-python = ">=3.12"

[project.scripts]
plating-qc = "plating_qc.cli:main"
```

`src/plating_qc/__main__.py` 전문:

```python
from .cli import main
raise SystemExit(main())
```

`cli.py`에서 확인한 계약:

- `python -m plating_qc [--config PATH] [--log PATH] <command>`. 전역 인자는 하위 명령 앞에 둡니다. 명령은 `probe FILE... --json`, `compare ORIGINAL CANDIDATE --out NEW_DIR --json`, `tiles INPUT --out NEW_DIR --cuts 48,120 --around 3`, `convert INPUT [--scene SCENE] [--suffix SUFFIX] [--dry-run]`, `split INPUT --out NEW_DIR --max-part-mb 400`입니다.
- 정상 결과는 stdout JSON, 오류는 stderr입니다. 종료 코드는 0=성공, 1=경고/검증 실패, 2=입력 불량, 3=출력 충돌, 4=실행 파일 없음/미지원, 5=디코딩/저장 실패입니다. 종료1을 성공으로 바꾸지 않으며, 이때 생성물이 존재하는 경우도 보존해 보고합니다.
- `--log` 생략 시에도 로그를 씁니다. `PLATING_QC_LOG_DIR`로 위치를 지정할 수 있습니다. 위임 시 툴킷의 새 출력 폴더 안으로 로그를 제한하고 참조 원본·raw·실행 폴더를 오염시키지 않습니다.
- 현재 backend는 ffmpeg입니다. Blender는 미구현으로 종료4입니다. compare의 불확실한 판정을 프레임 누락의 확정으로 바꾸지 않습니다.

CLI를 argv 배열로 부르는 얇은 경계를 첫 후보로 삼고 프로세스의 stdout/stderr·종료 코드·생성물·로그를 보존하는 계약을 제안해 주세요. shell 문자열 조립과 `backend/` 내부 API 의존을 피합니다. 다른 안이면 경계와 필요성을 설명합니다. 기존 QC 구조 변경은 별도 제안으로만 남깁니다.

## 6. 제약과 설계 원칙

- Python 3.12. `argparse`, `pathlib`, `tomllib`, `json`, `csv`, `urllib`, `subprocess`, `unittest` 등 표준 라이브러리를 먼저 검토합니다. 신규 설치·기존 환경 설정 변경을 전제하지 않습니다.
- 사용자 요구는 Interface/abstract class와 얕은 의존입니다. 입력·규칙 읽기·골격 조립·게이트·URL 검사·버전 검사·QC 위임 중 실제로 교체나 검증이 필요한 경계에 작은 계약을 둡니다. 깊은 상속, 한 줄 처리를 포장하는 메서드, 쓰지 않는 범용 플러그인 기반은 만들지 않습니다.
- CLI 하나(계획 이름 `plating`), 루트 설정 `plating.toml`을 후보로 합니다. 입력 문서·프로젝트 자료 루트·출력 루트·QC 실행 방법의 필요 항목만 제안합니다. 규칙 본문·단가는 정본 문서에서 읽습니다. 이번에 기존 `config.toml`은 변경하지 않습니다.
- Windows의 공백·한글 경로, UTF-8, CRLF/LF를 다룹니다. 상대 경로 기준을 명시하고 junction/링크를 해석한 뒤에도 입력 자료나 `raw/` 안으로 출력하지 않는 설계를 제시합니다.
- 원본 불변·기존 결과 덮어쓰기 금지. `raw/`는 읽기만 하며 로그·캐시·실패 임시 파일·QC 위임 출력도 쓰지 않습니다. 생성물은 명시한 새 출력 아래로 제한합니다. 중간 실패 시 반쪽 결과를 완성으로 공개하지 않습니다.
- 이번 작업의 쓰기는 `C:\Users\uicus\Dev\plating-qc-workflows` 안에서만 가능합니다. `Dev\dot-handoff`, NS-Plating, D:, G:는 읽기 전용입니다. 자료 속 옛 PC 쓰기 허용은 이번 권한을 넓히지 않습니다.
- 문서·로그·소스에 API 키를 넣지 않습니다. 문서·URL·파일명을 명령으로 실행하지 않습니다. 외부 서비스 이용 가능 여부와 잔액을 자료만 보고 단정하지 않습니다.

## 7. 확인된 충돌·부족과 처리

1. **이미지 태그**: H §5-4(542행)에 옛 `@[이미지 N](image_N)`이 남아 있습니다. W02 43행·W07 31행과 H §5-13(918행)은 `@image1` 순서입니다. AICRON용은 후자를 사용하는 요구로 두고 옛 표기를 조용히 채택하지 않습니다. 원본은 수정하지 않습니다.
2. **고해상도 생성**: H 120행에 480p 생성 결정과 1080p 본 생성의 옛 설명이 함께 있습니다. W02 79행·W06 70행·H 70행은 480p 생성 후 업스케일입니다. 480p는 이번 기본 요구, 1080p는 별도 명시 지정으로 두며 현재 서비스 사양의 검증된 사실과 구분합니다.
3. **블록과 설정 수치**: W10 144~146행은 옛 조리대 6.0×1.4m, W11 49행은 2.4×0.9m입니다. W10 STYLE/AVOID는 고치지 않으며 문제의 SCENE 모듈을 쓸 때 충돌을 알립니다. 프로그램이 정본을 고치거나 근거 없는 치환을 하지 않는 계약을 제안해 주세요.
4. **최신과 고정 예외**: S#10 v50 유지와 v2i는 단일 숫자 최댓값 규칙만으로 처리할 수 없습니다. 범위·출처가 있는 예외, 순서 불명, 같은 번호이지만 내용 미확인을 구분합니다.
5. **미확인 입력·환경**: 실제 컷표 원문, md의 색·토글 표현, 개별 이미지 공개 URL·동일성, 실제 디렉터리 최신 파일, 서비스 글자 수 상한은 미확인입니다. 값을 보충하지 말고 설계를 진행할 가정과 구현 전에 필요한 답을 구분해 주세요.
