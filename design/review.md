# 검수 및 1차 구현 범위

Claude 프로젝트의 03 설계는 `probe`와 `convert`부터 구현한다. 설계는 파일 존재 확인 후 이름 변경을 기술하지만 동시 실행 중 이름이 만들어지는 경합이 있어, 임시 파일을 같은 폴더에 만들고 최종 경로에 하드링크를 원자적으로 생성한다. 파일 시스템이 하드링크를 지원하지 않으면 안전하게 실패한다. 실패한 임시 파일은 제거한다.

표준 라이브러리만 쓰기 위해 테스트는 pytest 대신 unittest를 사용한다. FFmpeg 인코더·디코더를 합성 입력으로 검증한다. Windows와 동기화 드라이브의 하드링크 지원 여부는 해당 환경에서 확인해야 한다.

프레임 속도 의심은 현재 두 ffprobe 속성의 차이만 보고하는 부분 검사다. PTS 간격 분석, genpts 복구, 로그 파일, Blender 폴백, 추가 명령은 미구현이다. 변환 결과가 필수 검증을 통과하지 못하면 최종 파일을 남기지 않는다. 형식적 검증은 화면·색의 시각적 동등성을 보장하지 않는다.

## 비교와 타일의 1차 구현 차이

비교는 64×36 회색 영상의 표본 평균 절대차를 사용한다. 반복 장면, 프레임 속도 차이, 낮은 유사도는 불확실로 표시하고 누락 수치 확정을 피한다. 밝기 정규화, 시간 기반 VFR 정렬, 중간 프레임 손실과 합성 혼합 프레임 자동 판정은 아직 없다. 탐색 범위 밖의 오프셋은 찾지 못한다. 정렬 결과는 근거 확인용이며 눈으로 원본과 대조해야 한다. 대용량 비교는 메모리 제한으로 거부할 수 있다.

타일은 새 출력 폴더에만 저장한다. `raw/` 출력과 기존 폴더 덮어쓰기를 막는다. 장면 전환 후보, 셀별 프레임 번호·타임코드, 비교 이미지와 자동 보고서 저장은 미구현이다. 컷 이미지의 파일명에 0 기반 프레임 범위를 쓴다.

## Windows 테스트 후 수정

`convert`와 `tiles`가 같은 layout 검증을 사용한다. 경로 구분자가 든 `raw` 설정은 출력 전에 거부한다. 타일은 새 출력 폴더의 임시 폴더에서 생성하고, FFmpeg에 경로 없는 파일명만 넘겨 부모 경로의 `%`가 패턴으로 해석되지 않게 한다. 성공한 파일은 덮어쓰기 없는 하드링크로 배치하고 실패 시 임시 파일과 이 실행에서 배치한 파일을 정리한다. 해당 파일 시스템의 하드링크 지원은 Windows에서 다시 확인해야 한다.
