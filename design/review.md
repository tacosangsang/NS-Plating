# 검수 및 1차 구현 범위

Claude 프로젝트의 03 설계는 `probe`와 `convert`부터 구현한다. 설계는 파일 존재 확인 후 이름 변경을 기술하지만 동시 실행 중 이름이 만들어지는 경합이 있어, 임시 파일을 같은 폴더에 만들고 최종 경로에 하드링크를 원자적으로 생성한다. 파일 시스템이 하드링크를 지원하지 않으면 안전하게 실패한다. 실패한 임시 파일은 제거한다.

표준 라이브러리만 쓰기 위해 테스트는 pytest 대신 unittest를 사용한다. FFmpeg 인코더·디코더를 합성 입력으로 검증한다. Windows와 동기화 드라이브의 하드링크 지원 여부는 해당 환경에서 확인해야 한다.

FFprobe가 제공한 프레임 PTS 간격의 표준편차 및 두 fps 값을 검토한다. PTS가 없으면 `+genpts`를 시험하고 생성 여부를 구분한다. 변환은 상대 PTS를 프레임별로 검증한다. 100000프레임 초과는 PTS를 검사하지 않는다. FFprobe가 제공한 시간은 원래 제작 시각을 보장하지 않는다. Blender 폴백은 미구현이다. 변환 결과가 필수 검증을 통과하지 못하면 최종 파일을 남기지 않는다. 형식적 검증은 화면·색의 시각적 동등성을 보장하지 않는다.

## 비교와 타일의 1차 구현 차이

비교는 64×36 회색 영상의 표본 평균 절대차를 사용한다. 반복 장면, 프레임 속도 차이, 낮은 유사도는 불확실로 표시하고 누락 수치 확정을 피한다. 밝기 정규화, 시간 기반 VFR 정렬과 중간 프레임 손실 확정은 없다. 인접 원본 두 프레임의 회색 선형 혼합과 비슷한 차이 프레임을 최대 1000개 검사하여 의심만 표시한다. 다른 혼합 방식·색 변화·업스케일에 대한 누락과 오탐이 가능하다. 탐색 범위 밖의 오프셋은 찾지 못한다. 정렬 결과는 근거 확인용이며 눈으로 원본과 대조해야 한다. 대용량 비교는 메모리 제한으로 거부할 수 있다.

타일은 새 출력 폴더에만 저장한다. `raw/` 출력과 기존 폴더 덮어쓰기를 막는다. 프레임을 선택하기 전에 0 기반 디코딩 번호와 원본 PTS 초를 그린다. 선택 프레임의 PTS와 시간 기준을 manifest에 기록하고 누락·중복으로 원본 식별이 불가능하면 출력을 거부한다. FFmpeg drawtext·글꼴이 필요하며 100000프레임을 넘는 입력은 거부한다. `compare --out`은 새 폴더에 JSON·텍스트 보고서와 정렬된 쌍의 좌우 이미지를 최대 10장 저장한다. 정렬이 불확실하면 보고서만 저장한다. 장면 전환 후보는 FFmpeg scene 점수(기본 임계값 0.3)와 PTS로 원본 프레임 번호에 연결해 `scene_candidates.txt`·manifest에 기록한다. 실제 컷인지 사람의 확인이 필요하다.

## Windows 테스트 후 수정

`convert`와 `tiles`가 같은 layout 검증을 사용한다. 경로 구분자가 든 `raw` 설정은 출력 전에 거부한다. 타일은 새 출력 폴더의 임시 폴더에서 생성하고, FFmpeg에 경로 없는 파일명만 넘겨 부모 경로의 `%`가 패턴으로 해석되지 않게 한다. 성공한 파일은 덮어쓰기 없는 하드링크로 배치하고 실패 시 임시 파일과 이 실행에서 배치한 파일을 정리한다. 커밋 0ebea80까지는 Windows C: 임시 폴더에서 확인됐다. 이후 변경 및 D:·동기화 드라이브는 재검증이 필요하다.

## ProRes 분할 1차 구현

ProRes만 스트림 복사 방식으로 분할하고, 사용자 지정 크기를 모든 조각이 지키는지 확인한다. 원본과 이어 붙인 각 조각의 모든 디코딩 프레임 해시가 일치할 때만 새 폴더에 배치한다. 예측 크기보다 조각이 커지거나 검증에 실패하면 결과를 남기지 않는다. 오디오 경계 및 편집기 재생은 검증하지 않는다. VFR 의심 영상은 거부한다. Windows 하드링크 및 D:·동기화 드라이브 검증은 남아 있다.

## 분할 오디오 경계 검증

Windows C: 임시 폴더의 커밋 9b01ddd 합성 테스트에서 48프레임은 14/14/14/6으로 보존됐다. 48kHz PCM 96,000샘플도 전체 보존됐으나 조각별 오디오 시작이 0/14.000/6.667/20.667ms였고 일부 오디오·컨테이너 길이가 영상 경계를 넘었다. Linux의 별도 48kHz PCM 합성 예제에서는 복원된 PCM을 순서대로 이어 붙였을 때 바이트가 원본과 같았지만, 패킷 간격은 주로 1024샘플(21.333ms)이고 영상 경계와 일치하지 않아 시작 위치·길이가 조각마다 달랐다. 이 실험은 다른 코덱과 편집기에서의 이음새를 보증하지 않는다.

기본 동작은 기존 스트림 복사를 유지한다. 오디오가 있으면 `manifest.json`과 CLI에 첫 번째 오디오 스트림 및 영상 시작·길이를 기록하고, 이음새 미검증 경고와 종료 코드 1을 반환한다. 영상 검증을 통과한 출력은 저장된다. 원본 오디오를 연속 트랙으로 두는 방법을 편집기에서 검토할 수 있지만 실제 이음새 검증이 필요하다. 여러 오디오 스트림의 시간 정보 전체는 표시하지 않는다.

## PTS와 혼합 프레임 검증

FFprobe가 제공한 프레임 PTS 간격의 표준편차가 평균 프레임 간격의 5%를 넘거나 PTS가 비증가면 VFR을 의심한다. 평균 fps와 표기 fps가 다를 때도 의심한다. PTS 누락은 genpts 재시도 후 generated/unavailable로 구분하며 생성된 시간은 원래 타이밍을 보증하지 않는다. VFR·미확인 시간은 프레임 번호 정렬을 확정하지 않고 split을 거부한다. 타일은 관찰된 PTS만 표시한다. 변환 시 시작점을 제외한 프레임별 상대 PTS 오차가 1ms를 넘거나 확인 불가능하면 최종 결과를 남기지 않는다. 전역 시작 시각과 오디오 동기는 이 검사 범위 밖이다.

혼합 프레임 의심은 주변 원본 두 장의 25/50/75% 회색 선형 혼합에 가까운 후보를 표시한다. 시각 검수용 힌트이며 실제 혼합 여부를 단정하지 않는다.

## 시작 시각 및 장면 후보

Windows C: 합성 검증에서 cfc06f5의 영상 절대 시작 시각이 2초에서 0초로 이동했다. 상대 PTS가 보존되어도 변환 결과의 절대 시작 시각이 입력과 1ms 넘게 다르면 경고한다. 오디오와 영상의 상대 시작 차이가 1ms 넘게 달라지거나 확인 불가능한 경우도 경고한다. 전 구간의 A/V 동기화와 편집기 재생은 보장하지 않는다.

타일은 scene 변화 점수로 장면 전환 후보를 별도 기록한다. 선택된 PTS를 원본 프레임 번호에 유일하게 연결할 수 없거나 처리에 실패하면 결과를 남기지 않는다. 장면 변화가 곧 컷이라는 뜻은 아니다.

## 실행 로그와 합성 예제

CLI 공통 `--log`는 별도로 지정할 때만 새 JSON 파일을 만든다. 설계의 기본 자동 기록·기존 로그 이어쓰기와 달리, 원본 및 기존 파일을 보호하려고 명시적 새 파일만 허용한다. 명령 인자·파일 경로, 실행 위치·시간, 결과·오류, 종료 코드, FFmpeg·ffprobe 버전과 소스 해시를 포함하며 환경 변수는 기록하지 않는다. 로그 파일을 공유하기 전 개인 경로를 확인해야 한다. 설정 읽기와 로그 예약 전에 일어난 오류는 기록할 수 없다. `samples/reproduce.py`는 시스템 임시 폴더의 합성 영상으로 다섯 명령과 로그를 재현하며, 실제 Linux 예는 `samples/README.md`에 있다. Windows 실행은 별도 검증이 필요하다.
