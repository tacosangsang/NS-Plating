# prompt-page

프롬프트 페이지는 손으로 HTML을 쓰지 않는다. 컷 하나의 JSON을 채우고 `prompt_page.py`로 만든다.
검사에 걸리면 HTML이 만들어지지 않는다. 빈 칸을 채워서 다시 돌린다. 검사를 피하려고 칸에 아무 말이나 넣지 않는다.

근거: 11-09 기존 프롬프트 페이지 18개 점검. 11개에 그림이 없었고, 점검 칸은 2개에만 있었다. 첫 섹션이 [최신]인 페이지는 6개였다.
사용자 지적: "사진도 잘 안보이고 구도/앵글/필요한 이미지도 안보여".

슬래시로 부를 수 있다: `/prompt-page`(만들기), `/prompt-check <링크 또는 JSON>`(점검).

## 순서

1. 컷마다 JSON 하나를 만든다. 형식은 `example.json`을 보고, 그 파일을 복사해 고친다. 예시의 `img_src/` 그림은 저장소에 없다.
2. 그림 파일(`file`)은 JSON 기준 상대 경로나 절대 경로로 적는다. `@video` 입력은 첫 프레임을 jpg로 뽑아 `file`에 넣는다.
3. 검사만 할 때: `python3 .claude/skills/prompt-page/prompt_page.py page.json --check`
4. 페이지를 만들 때: `python3 .claude/skills/prompt-page/prompt_page.py page.json <출력폴더>`
   - 출력되는 JSON의 `file_path`, `files`, `capabilities`(`{"downloads": true}`)를 Artifact publish에 그대로 넘긴다. capabilities를 빼면 원본 받기 버튼이 꺼진다.
   - 같은 페이지를 고칠 때는 같은 `file_path`로 다시 publish한다.
5. 새 판을 만들면 `generations` 맨 앞에 넣고, 앞의 판은 status를 바꾼다(대안/완료/옛 판/실패). 한 페이지에 컷이 여럿(A1·A2·A3 등)이면 판마다 `cut`에 컷 이름을 적는다. 페이지는 컷마다 따로 여닫는 칸(처음엔 모두 열림)을 만들고, 컷 안에서는 맨 앞 판과 최신·생성 대기 판을 펼치고 같은 컷의 옛 판·대안만 "이전 판"으로 접는다. 다른 컷은 끝났어도(완료) 이전 판으로 숨기지 않는다(사용자 11-10). 컷이 하나면 `cut`은 비워도 되고, 최신·생성 대기 판은 모두 펼쳐진다.

## 칸

| 칸 | 내용 |
| --- | --- |
| `kind` | `video`(영상 생성) / `video_edit` / `image`(Seedream Edit·Combine) |
| `status` | 최신 / 생성 대기 / 대안 / 완료 / 옛 판 / 실패. 맨 위는 최신이나 생성 대기여야 하고, 최신은 하나만 |
| `cut` | 컷이 여럿인 페이지에서 그 판이 속한 컷 이름(예: A1). 같은 컷의 판끼리 같게. 컷마다 맨 앞 판이 지금 상태여야 하고(옛 판·대안 불가), 최신은 컷마다 하나 |
| `inputs` | 프롬프트가 부르는 @image·@video 전부: tag, role(시작 프레임/시트/배치만 등), path(프로젝트 경로), resolution, file(보이는 그림, 원본 최고화질). 고른다면 blockout(버전), original(받을 파일이 보이는 그림과 다를 때, 예: @video의 원본 mp4) |
| `shot` | 한글로 쓴다: 샷 크기, 카메라 위치·높이, 앵글, 렌즈, 카메라 움직임, 화면 배치, 빛 방향. 구도를 @image1에서 그대로 쓰면 `same_as`에 한 줄. `refs`에 레퍼런스·블록아웃 렌더 그림 |
| `beats` | 영상 생성일 때 필수. t(초) / camera / action(원인 → 행동) / sound(대사·효과음) / end(끝 상태). 마지막 초는 length_s와 같아야 한다 |
| `beats[].camera` | 영상 생성일 때 구간마다 필수(사용자 11-10). 그 구간에 카메라와 화면이 어떻게 바뀌는지. 0초 구간 = 시작 프레임 구도, 중간 = 인물·배경이 어느 쪽으로 얼마나 밀리는지(예: 화면 폭 1/3→1/2), 마지막 = 감속·정지 지점과 끝 구도. "계속"·"유지"·"동일" 같은 빈말은 검사에서 걸린다. 같은 내용을 프롬프트 TIMELINE 각 줄 끝에 `Camera: ...`로 쓴다(구간 수만큼 없으면 걸린다) |
| `check` | 핸드북 "크레딧 쓰기 전 점검" 8줄 순서대로 예/아니오/해당 없음. 아니오면 note에 이유와 대안 |
| `prompt` | 전문. 글자 수와 장수는 페이지가 계산한다. 가면 쓴 인물(상류층 조류 가면, 흰토끼)이 나오면 `prompt_page.py`의 `MASKS_BLOCK` 원문을 STYLE 바로 뒤에 넣는다. 부리가 입을 가린 인물의 컷은 대사 없이 몸짓·눈으로만 쓰고 `MASKS_SILENT_BLOCK`(입 낱말 없는 판)을 넣는다. 가면 인물과 맨얼굴 인물(진우·하층민·도둑·요리사 등)이 한 화면이면 원문 대신 `masks_only("the white rabbit")`처럼 조항을 가면 인물에게만 한정하고, 맨얼굴 인물마다 NO MASK 줄과 얼굴(하층민·도둑은 FACE RULE)을 적는다. 원문이 "every person"이라 맨얼굴 인물에게도 가면이 생긴다(RS06, 11-11). 셋 다 없으면 검사에서 걸린다(사용자 11-10, 부리가 입처럼 벌어지는 것 방지) |
| `result` | 생성 뒤 결과 그림·영상(media)과 2~3줄 판정(verdict) |
| `notes` | 긴 비평과 바뀐 이유. 접힌 칸에 들어간다 |

## 페이지가 지키는 것

- 입력 그림은 한 줄에 한 장, 페이지 폭 가득, 긴 변 1600px로 보인다. 작은 격자는 없다.
- 올리는 그림·영상(입력, 레퍼런스, 결과 전부)마다 **원본 받기** 버튼이 붙는다. 원본은 손대지 않은 파일 그대로 `orig/`에 올라가고 버튼에 해상도·크기가 보인다(사용자 11-09). 파일 하나가 15MB를 넘으면 아티팩트에 못 올리므로 검사에서 걸린다.
- 그림 아래에는 @번호·역할·경로·해상도가 붙는다.
- 프롬프트 바로 위에 점검 칸이 있고, 아니오는 빨간색으로 보인다.
- 복사 버튼이 붙는다.
- 다크 모드를 지원하고, 휴대폰 폭에서도 볼 수 있다.

## 검사기가 못 보는 것

검사기는 칸이 찼는지만 본다. 다음은 점검 칸에서 직접 확인한다.

- mm·앵글이 맞는지
- 입력이 가장 큰 원본인지
- 컷표 문장과 맞는지

새 생성 종류(업스케일 등)가 생기면 `Kind`를 상속한 클래스를 하나 추가하고 `KINDS`에 넣는다.
